## 1. 使用场景与目标

用户在一个新的 Codex 会话中给出积分和目标。这个会话就是求解 AI：自行规划路线，在计算环境中调用 Python、Mathematica 等工具探索，先在 MD 中整理一段推导，再按单步或小批次调用 Wilson MCP 验证。中途发现问题时修改草稿、调整探索方向，继续长段推导，再逐段提交。提交时机由求解会话决定，不要求每写一个等号就等待验证。Wilson 不另建一个求解 Agent。

求解 AI 不需要知道 Lean，不提交 Lean 代码、tactic 或 Mathlib 定理名，也不修改 Wilson 源码。它需要掌握的只有数学工具协议：公式、变量范围、定义、变换和步骤引用。

分层目标：

1. **初等微积分首版**：在明确支持的操作和定义域内，严格验证一组普通积分的推导链。
2. **2e-02 首版**：从给定原积分 J，经当前单一 C/I 约定，验证到 I 的零阶、一阶展开系数及其 M 表示。
3. **2ne 推广**：以新增真实积分验证可复用性，逐步声明支持的积分族和展开阶数。不能把一个 2e-02 实例的成功推广为任意图、任意圈数或全部洛朗系数。

“保障正确”指：精确数学陈述在记录的根假设下具有可复核证明，且证明连接到指定原问题。其保证依赖正确的输入语义、固定证明环境和检查器。它不承诺自动解出所有积分，也不把未知判为错误。

## 3. 架构与职责

2026-09-12 补充决定：采用通用关系组合、条件与数学操作、具体函数定理库、问题定义四层。验证局部变换不应要求完整求值；具体 Gamma/Beta 等函数定理允许且应复用，避免积分编号或固定完整答案专用规则。此重构尚未实施；当前执行顺序及验收以 [总计划 3.5 与 P4](master-plan.md) 为准。下文早期阶段编号保留作设计历史。

```text
新 Codex 会话：理解问题、探索、提交数学步骤
                     |
                 Wilson MCP
                     |
          数学对象、上下文、任务与步骤接口
                     |
          有界规则匹配、条件处理、证明生成
                     |
       Mathlib + Wilson 通用定理 + 积分实例定理
                     |
            Lean 检查、证据存储与整链检查
                     |
              数学反馈、收据、恢复入口
```

- **求解会话**负责选方法和计算候选；允许与参考 MD 不同的路径和表达式。
- **数学接口**负责明确类型、变量绑定、积分域、分支、定义和依赖。首版使用受限结构化数学表达式；展示公式与被检查对象保持对应，不承诺任意 LaTeX 自动无歧义解析。
- **验证调度**先匹配可复用证据，再为未获证的操作或连接生成证明。分别检查操作本身和调用之间的数学连接，不要求重新求解已获证的计算。搜索有预算；失败返回未解决事项，不要求调用者调试 Lean。
- **数学库**优先复用 Mathlib。Wilson 保留通用桥接定理及 J、C、I、M 等领域定义和连接定理。
- **证据层**复用现有不可变收据、环境指纹和依赖检查。缓存必须绑定精确陈述、上下文、规则和环境版本。
- **CAS/数值工具**用于探索与辅助排错；输出不自动进入正式证明链。首版正式验收统一由 Lean 复核，其他证书检查器以后按具体需要评估。

实验 A 至 I 作为回归和历史证据保留，不再把实验编号作为公共 API 的组织方式。先整理职责和入口，物理移动文件仅在有实际收益时进行。

## 4. 对外协议和正确性约束

### 4.1 MD 探索与验证循环

默认工作流为：**自由推导并写入 MD → 选择一段数学步骤提交 → 读取逐步反馈 → 修订或另开路线 → 继续探索与验证 → 对选定路线做整链验收**。

MD 是求解会话维护的可修改工作笔记，可包含猜想、未验证推导、失败路线和解释。Wilson 保存的是不可变的数学陈述、上下文和证明收据。MD 中的“已验证”文字不构成证据；提交时由会话将公式整理为结构化数学请求，服务返回实际检查的对象供对应。首版不增加任意 MD 自动解析器。

同时保留两种进度：

- **探索进度**：草稿和各候选分支推到哪里，允许超过验证进度。
- **验证进度**：各分支哪些步骤已有有效证据，以及哪些已连接到原问题。它是依赖图上的状态，不是简单的“最后一行已通过”。

连续代数整理可以合成一个提交目标；换元可将映射、微分、上下限和表达式整理组成一批。交换积分、积分下求导和分支改变等关键操作建议及时检查，减少沿错误前提继续探索的成本，但不强制改变会话的推导节奏。工具调用后会话可以继续推导；效率影响通过真实任务测量，不假定批量总是更快。

### 4.2 单步、批量与草稿修订

接口同时支持单步和有界批量。批次中若提交多个步骤，必须分别检查各步及其依赖，不能只检查首尾相等。响应逐步返回状态、收据和未解决事项；依赖未获证步骤的项应标明阻塞，独立项可以继续检查。成功项独立保存，不因同批其他步骤失败而丢弃；这是待实现的公共行为，不能假定现有内部批次已经具备部分成功语义。

草稿使用稳定的步骤标识及修订标识映射服务对象，行号只作定位。请求绑定不可变的陈述、定义、条件和父步骤版本；服务以接收时的快照验证，不能把稍后返回的旧版本结果自动贴到新草稿上。异步回复也必须携带对应请求和修订标识。

修改第三步时，第一、二步以及不依赖该变化的证据仍可复用。旧第三步收据继续证明旧陈述，不被删除或改写；新第三步另建版本。旧后继不能自动算作新路线已获证，应检查受影响的依赖闭包。若重新建立了精确前提或等价桥接，可复用已有证明，无须一律重新求证全部后继。只改文字或排版且结构化数学对象未变时，不使证明失效；判断不能只依靠 MD 文本哈希。

允许保留旧路线并从可靠节点建立新分支。新窗口恢复时应能找到草稿位置/修订标识、探索分支、服务中的精确目标和验证状态；草稿缺失不损坏已有证明，但服务不能据此声称恢复了尚未提交的探索内容。

### 4.3 数学协议与证明边界

首版工具应覆盖以下职责；具体名称和字段在接口阶段冻结：能力查询、创建/恢复任务、提交数学步骤、读取步骤状态、检查整条推导。

每个任务记录原始目标、精确积分定义、变量域、根假设、当前归一化版本、目标展开阶数和可选输出形式。每步记录前后陈述、引用步骤、可选的数学说明（例如原函数或换元映射）。

AI 不传内部策略名。像 `transitivity`、Lean 参数实例化和证明拼装等机制由服务内部完成。求解端反馈使用数学语言；源码、编译日志、tactic 留在维护诊断中。

| 状态 | 含义 |
|---|---|
| 已验证 | 精确目标已获证，返回收据及所依赖条件；是否接入原任务另有链路状态 |
| 待补充 | 返回尚未解决的数学条件或中间关系；建议条件不冒充唯一必要条件 |
| 暂不支持 | 表达式或操作超出能力范围 |
| 未解决 | 在预算内未获得证明，也未获得反证 |
| 已反驳 | 有可检查的反例或反证 |
| 请求无效/执行失败 | 语法、依赖、存储或运行问题，不解释为数学错误 |

正式整链验收必须满足：

1. 每步证明针对实际提交的陈述，而非替换成预置答案。
2. 每步前件通过精确对象或已证等价关系连接上游；不能只检查最终值相同。
3. 新条件必须从根条件推得，或显式形成条件化分支；未解决条件不能关闭原目标。定义不能在同一任务中静默变更。
4. 变量类型、自由/绑定变量、定义域和分支保持一致；开放区间恒等式不能直接假装满足闭区间全部前提。
5. 所需证据均有效且可重放；过期、损坏、缺失依赖不能获得完整状态。展示用文本或输入哈希本身不证明数学等价。
6. 条件化证明明确标注根假设；已检测到矛盾的上下文不得产生有意义的“原任务完成”结论，不承诺一般假设一致性可自动判定。
7. 若要求 M 表示，必须证明系数与该表示相等；生成子格式和参考路径不是唯一合法路线。

物理图到积分、颜色因子、重数和运动学分支来源单独记录。首版可以验证给定数学积分，但不能把它描述成 P-06 已获证。

### 4.4 工具计算与长程推导连接

MCP 是调用协议，不是正确性证明。函数名为 `integrate`、调用成功或多个引擎答案一致，均不自动意味着原任务已经严格解决。需要区分两个检查对象：

- **操作内部**：工具是否为实际输入给出了正确结果，适用条件和证据覆盖到什么程度。
- **操作之间**：实际输入是否由此前的原问题合法得到，结果是否在相同定义、参数范围、分支和精度语义下被使用。

例如原题为 ∫₀¹ 2x exp(x²) dx。若会话令 u=x² 却错误提交 ∫₀¹ 2exp(u) du，工具正确返回 2(exp(1)−1)，也不能解决原题。Wilson 应拒绝遗漏 du=2x dx 的换元连接；该工具结果可以作为另一个积分的结论保留，不能挂到原链上。

一次调用可以封装完整积分计算，不要求会话展开成熟算法的全部内部步骤。若有针对该精确积分的可接受证明，可以作为一个获证节点接入。若会话显式提交了内部推导，则仍按其实际步骤检查，不能用独立正确的首尾结论掩盖错误路线。

| 返回材料 | Wilson 的处理 | 能否直接关闭正式义务 |
|---|---|---|
| 当前有效的 Wilson 收据 | 核对陈述、上下文、环境及依赖，匹配后复用 | 可以，不重复求解；仍检查与本任务的连接 |
| 外部工具提供的证明或计算证书 | 通过已支持的适配器核验来源绑定、目标语义和证明；首版需要 Lean 可复核的路径 | 核验成功后可以；尚无适配器时保留为待核验证据 |
| CAS 符号答案或精确算术输出，无可接受证书 | 保存候选结果与条件，按正式目标生成证明 | 不可以，精确算术标签不等于整步分析证明 |
| 数值结果、区间或有限阶展开 | 记录精度、误差界、展开阶数及其依据 | 只可能支持相应数值/近似陈述，不能自动证明精确恒等式 |

证据的采用由 Wilson 的检查策略决定，不能由求解会话填入 `trusted=true` 或工具自报“已验证”决定。外部证书核验能力是后续按需接入的适配能力，不是当前现成支持。核验一份证书与重新搜索整个解法是不同工作。

工具结果关联记录至少包括：精确输入输出、操作、数学上下文、工具及版本（能获取时）、调用记录、证据种类和范围、关联任务/步骤。调用记录证明执行来源，不单独证明数学结论；缺失必要语义时不能猜测。请求/结果绑定使用不可变对象，避免把相似但不同积分的结果误用。

接入原任务时，服务还需证明或匹配：换元及 Jacobian、上下限、前因子、变量定义、假设蕴含关系、分支以及近似语义。它们是数学连接，不是仅凭字段相同即可完成的检查。尤其对 2e-02，C/I 归一化、尺度因子和展开系数的组合也属于这条连接链。

只有操作证据和所需连接均成立，才能把该节点计入原任务的正式验证进度。已获证的孤立结果可以复用，但不会自动使整链完成。缺失的连接应反馈为具体待证关系或未解决事项，不一律判定结果为假。

## 5. 实施阶段与验收

### K0：整理基线与模块边界

交付：现有模块职责清单、运行入口/实验工具/历史材料分类、重复请求的迁移表、待提交工作说明。每项标注保留、包装、逐步替换或历史保留及其理由。

同时按复用分析登记第三方组件的实际来源、版本/文件指纹、许可、运行依赖与接入状态，区分源码已下载和实际可用。

验收：能从唯一计划入口定位当前状态、公共接口和回归入口；不删除历史证明与原始推导，不无故改变绑定证据的历史文件。迁移清单列出每个旧入口对应的新入口及停用条件。

### K1：数学接口、MCP 与新会话闭环

交付：数学请求/反馈契约、受限表达式规范、内部规则路由、任务恢复接口、面向新 Codex 会话的简短使用说明。契约包含单步/批量提交、逐项结果、部分成功保存、草稿步骤/修订映射和分支依赖，并区分操作证据状态与原任务连接状态。首期复用 Wilson 自有收据、记录外部工具候选；不以实现所有外部证书适配器为 K1 前提。先接入现有能力，再按验收例子扩展。

验收：新会话只凭工具说明和数学题完成一个普通积分及一段已有 2e-02 推导；不读写 Lean，不传 tactic，不修改服务源码。另一个新会话仅凭任务 ID 可恢复目标、条件、步骤和收据。错误引用、条件丢失、定义变更及断链均不能获得完整状态。

MD 循环的专项验收：

1. 会话先写含多个步骤的草稿，再分批提交，过程中不要求每个等号调用工具。
2. 一批中前两步通过、第三步失败时，保留前两步收据，阻止其依赖后继获得完整链路状态；同批独立项仍可验证。
3. 会话根据反馈修改第三步并继续长段推导；新路线只复用条件和依赖仍匹配的旧证据，最后能完成整链检查。
4. 旧版本的延迟回复、草稿中伪写的“已验证”和复制的无关收据均不能把新步骤升级为已验证。
5. 纯文字修订不触发数学证明失效；条件或定义变化会触发受影响链路重检。新会话恢复时能区分草稿探索进度与正式验证进度。

第三方参考落地：参考 MathKernel 的上下文继承及证据组合测试，增加“可选检查失败不抹掉已完成证明”“未核验脚本不获证”的回归。MCP 传输库单独做最小兼容验收，不整体迁移 MathKernel 的运行时。

### K2：初等微积分验收集

| 积分 | 目标 | 验证能力 |
|---|---|---|
| ∫₀¹ x dx | 1/2 | 原函数、FTC、端点求值 |
| ∫₀¹ (2x+3) dx | 4 | 线性、组合与代数 |
| ∫₀¹ 2x exp(x²) dx | exp(1)−1 | 非线性换元或链式求导＋FTC |
| ∫₁ᵉ log(x) dx | 1 | 分部积分、定义域 |
| ∫₀¹ xᵃ dx，a>−1 | 1/(a+1) | 参数、端点与可积性 |

这些是待验收能力清单，不表示现有服务全部支持。每题都走同一数学接口，不硬编码答案。规则至少在一个不同参数或不同表达式实例中复用；至少一题验证两条不同路线。

实现优先直接调用现有 Mathlib 的求导与 FTC。Alkahest 的导出器和 symbolica-integrate 的步骤输出只作有界适配评估，详见复用分析。加入“导数残差是非零常数”的负例：F=x²/2+x 不能作为 x 的原函数；不能照搬第三方 RL 评分标准作为正式判定。

验收：五题完整获证；配套错误答案、漏雅可比、非法约分、缺少条件案例不获完整收据。可证明错误的案例返回反证，其余如实返回未解决或待补充。正确最终答案配错误中间步骤仍不能通过该条链的验收。

工具组合的专项验收：

1. 对同一积分引用当前有效收据，不再次调用 CAS 求解或启动证明搜索；记录证据复用与必要连接检查。
2. 工具正确计算了错误换元后的积分时，该局部结果与原问题的连接被拒绝，不能输出整链通过。
3. 在 a>0 下获得的条件化结果被用于未满足该条件的上下文时，不自动接纳；返回缺少的条件连接。
4. 漏乘前因子、跨版本符号定义、跨复分支使用结果、把有限阶近似当精确等式，均不能获得错误的完整状态。超出首版表达能力的分支案例应返回暂不支持，不能静默接受。
5. 仅附 CAS 输出或自报可信标签不能获得正式收据；给出匹配的有效收据后能作为完整操作接入，无须强制展开内部算法。

### K3：2e-02 首期全链路

交付顺序：

1. 将实验 I 局部分子恒等式与已有 I-beta 完整核建立定义对应。
2. 接入积分下几乎处处相等、端点和可去点处理。
3. 定义首期 M-family 并证明需要的可积性。
4. 证明有限阶参数求导与积分交换，得到当前 I 的零阶、一阶系数。
5. 连接原 J、新 C/I、降维表达式和系数，输出整链报告。

验收：报告明确参数范围、归一化、展开阶数、每个系数的精确定义和依赖；目标数学链无未解决的必需义务。若只证明值与一阶导数，不宣称已证明 O(ε²) 余项；更强余项需要额外证据。若展示带尺度前因子的洛朗系数，还需证明前因子展开与系数组合。

此前 C-01 至 C-08 回归保持有效。至少一个非参考形式的中间表达式通过等价桥接接入。P-06 未关闭时，报告明确这是给定积分与约定下的数学结论。

### K4：2ne 积分族推广

先从实际目标中登记至少两个额外积分实例，写清输入、参数域、目标系数阶数及其与 2e-02 的结构差异；实例选定前不声称已覆盖某一整个积分族。

交付：通用规则复用清单、实例专用定义/定理清单、能力边界表。

验收：新实例走同一 MCP 协议；每个声明支持的目标具有完整证据链。新定义可以增加，但不按积分编号另造一套验证器。实参数范围、解析延拓、复分支和更高圈数分别验收。

## 6. 性能与回归

从 K1 起记录冷启动、缓存命中、预热后的新步骤、整链检查和独立重放耗时。记录硬件、环境指纹、样本数及中位数/P95，明确是否包含构建。对同一组数学步骤比较单步与批量提交的总耗时、工具调用次数和失败后重检范围；批次耗时与单步指标分别报告。

优先预编译稳定模块、按依赖复用构建产物、仅检查新增证明。正常请求不应无条件重复编译全部 Wilson 模块。分别计量已有证据核对、连接补证与新操作证明，避免重复调用积分求解器来替代证据复用。缓存失效与独立重放仍保留完整检查。

初始工程目标（待实测，不是现有承诺）：本地预热后重复请求 P95≤1 秒，K2 常规新步骤 P95≤5 秒；复杂分析证明允许异步返回任务 ID。达不到时应报告实测和瓶颈，不以减少证明检查换取表面速度。先使用固定不少于 30 次的请求样本，并区分命中与新请求。

迁移回归包括：原有数学目标、上下文和依赖负例、篡改/过期证据、独立重放，以及新会话的真实 MCP 调用记录。单元测试和静态构造请求不能替代新会话验收。
